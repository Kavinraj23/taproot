# 0004: Run the OTel demo without its own observability stack

- **Decision:** `scripts/up.sh` starts the demo with `compose.yaml` + `compose.full.yaml` + `compose.extras.yaml`, the same set as the demo's `make start-no-o11y`, plus Taproot's memory override. It leaves out `compose.observability.yaml`: OpenSearch, Jaeger, Prometheus, the demo's Grafana and opamp-server. All the application services, Kafka and the demo's OTel collector still run. Without the observability layer, the collector exports only to its `debug` exporter, so it needs no config change and stays available as Taproot's trace source in M4. `scripts/check-demo.sh` now checks memory at the Docker VM level (available memory and swap), not just inside containers.
- **Why:** On 2026-11-12, after a few hours with the full demo plus Taproot under the 6 GB Docker cap, the VM had used 2013 of its 2048 MB swap with 74 MB free. VM CPU sat at 50–90% with no added load, ClickHouse stopped answering queries, and the agent missed ticks. Taproot's pipeline lost nothing: Redpanda and ClickHouse counts matched. The 2026-11-04 memory check had measured about 4 GiB inside containers. That number leaves out the VM's kernel, file cache and swap, so it under-reported the pressure. OpenSearch alone was about 1 GB. These backends duplicate what Taproot is being built to do.
- **Replaces:** Section 4 (Scope) and section 5 (Deployment). "The full demo" now means the full set of demo services (including Kafka and the three failure scenarios), without the demo's own observability backends. The 6 GB Docker cap stays.
